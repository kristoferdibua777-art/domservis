# Дом-Сервис: старт для разработчика

Эта документация предназначена разработчику и его AI-ассистенту, которые получают проект
без истории предыдущих обсуждений. Она объясняет устройство форка и путь от задачи до проверенного изменения.

Сверено 2026-09-06 с кодом приложения cdc71a1bd8.
Состояние конкретного VPS, его базы и секретов сюда не входит.

## Что это за проект

Дом-Сервис — модуль выездных работ поверх Zammad:
диспетчер публикует заявку, мастер берёт её или получает назначение, выполняет и закрывает.
Собственная доска управляет оперативным состоянием, связанный тикет даёт историю и инструменты Zammad.

Основной код доски находится в legacy CoffeeScript/Spine/ECO, а не в Vue.
Наличие Vue-приложений в репозитории не означает, что нужно начинать правку доски с них.

## Что получить при передаче проекта

- Доступ к репозиторию приложения и репозиторию Docker Compose.
- Возможность запуска GitHub Actions и публикации GHCR, если нужно выпускать версии.
- Текущий commit приложения, тег образа и revision конфигурации запуска.
- Адрес тестового окружения либо возможность поднять его локально.
- Тестовые учётные записи разных ролей.
- Для эксплуатации — отдельно адрес VPS, способ входа, каталог Compose и место резервных копий.

Секреты передаются отдельно от документации. Исторические локальные заметки владельца не являются
обязательной частью проекта и не должны требоваться для запуска с нового компьютера.

## Первая рабочая сессия

1. Прочитать этот файл, архитектуру и ограничения.
2. Проверить ветку, remote и незакоммиченные изменения в обоих репозиториях.
3. Поднять выбранное локальное окружение.
4. Пройти сценарий диспетчер → пул → мастер → завершение.
5. Проследить одну операцию от UI через API до DispatchJob, DispatchEvent и Ticket.
6. После этого брать конкретную задачу и выбирать точку изменения по карте кода.

Не начинайте с переписывания интерфейса или полной синхронизации с upstream:
это отдельные задачи с собственной приёмкой.

## Шаблон задачи для AI-ассистента

```text
Прочитай developer.md, doc/dom-servis/architecture.md и doc/dom-servis/limitations.md.
Задача: [конкретное изменение].
Сценарий: [роль, начальное состояние, действие, ожидаемый результат].
Окружение: [локальное / тестовое], ветка: [ветка].
Сначала найди действующий UI → маршрут → контроллер → политику → модель/сервис.
Проверь, затрагиваются ли backing ticket, события, realtime и уведомления.
Внеси минимально необходимое изменение, выполни целевые проверки.
В результате перечисли файлы, изменившееся поведение, выполненные проверки и ограничения.
```

## Что считается завершённой задачей

- Описан проверяемый результат для пользователя.
- API и UI соблюдают права и видимость записей.
- Не потеряны проекция в тикет, события и нужные уведомления.
- Выполнены проверки соответствующего слоя; непроверенное указано явно.
- Новые настройки работают при чистой установке и обновлении.
- Документация изменена вместе с контрактом функции.
- Для выпуска выбран конкретный проверенный commit; успешная сборка не подменяет приёмку.
