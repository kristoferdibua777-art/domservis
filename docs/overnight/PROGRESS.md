**Задача 1 — пуши на Android** (коммит `e36137a`). Диагноз по коду (логов устройства пока нет):
1. Подписка сохранялась до входа в систему → сервер отвечал 401 → браузер подписан, сервер про
   устройство не знает → пуши не приходят. Исправлено: окно ждёт `/api/v1/users/me`, при уже
   выданном разрешении тихо пересохраняет подписку.
2. `Urgency: normal` → FCM может задерживать сообщения, пока Android в режиме Doze.
   Исправлено на `high` ([Firebase: приоритет сообщений](https://firebase.google.com/docs/cloud-messaging/customize-messages/setting-message-priority)).
3. Цветная иконка как `badge` → на Android белый квадрат в строке состояния. Убрано.
4. Клик по уведомлению теперь открывает нужную ссылку в уже открытой доске.

Окно разрешения переделано в нижнюю шторку: тёплая палитра, контраст WCAG AA (4.7:1),
кнопки 48 px, учёт выреза экрана, инструкция при запрете, «Позже» скрывает на 3 дня.
Скриншоты: `screenshots/push-sheet-360.png`, `screenshots/push-sheet-412.png`.

**Как проверить на Android после деплоя ветки на тестовый стенд:**
войти → «Разрешить уведомления» → в доске нажать «Тест пуша» → заблокировать экран на 5 мин →
создать заявку → уведомление должно прийти сразу.

**Не проверено:** RSpec/QUnit не запускались (нет поднятого Zammad в контейнере).
VAPID-ключи на сервере не проверялись (нет доступа к VPS) — если `dom_servis_webpush_vapid_public_key`
пустой, окно не появится вовсе.

**Замечено, не трогалось (решение за Иваном):** в `layouts/dispatch_board.html.erb` путь к
`application-11ea6e…js?v=push2` захардкожен с хешем сборки. После пересборки ассетов файл сменит имя
и доска не загрузится. Лучше `javascript_include_tag "application", defer: true`.
